# RightCash-Lean

A Lean 4 model and correctness proof of the
[RightCash](https://github.com/qusuyan/RightCash) authenticated write-set
storage engine, which is included as the submodule `rust/` at the commit the
proofs are about.

The specification, assumptions, results and proof architecture are in
[SPEC.md](SPEC.md). In short, for both v0 eviction policies (FIFO and
LRU-write), and for every capacity, low watermark and choice of hash
functions:

1. **Root binding.** Equal roots imply equal write sets, eviction-policy
   states and storage states, unless a hash collision has been found. This
   covers the initial node too, including one opened over an engine that
   already holds state.
2. **Deterministic transitions.** Equal roots plus the same batch imply equal
   next states and equal next roots.
3. **Independence from prefetch.** The state after `Propose` depends only on
   the parent's state and the batch, never on prefetch hints, speculation
   worker timing or worker failures.

`Revision(root)`, which also resolves an empty-set node by its storage root,
returns nodes that read identically. When `root` is a combined root, they
also have the same consensus state. If every batch writes at least one key and
the low watermark is at least 1, they have the same consensus state in every
case (assumption A7).

These also hold for the **concurrent** system: a separate worker thread
behind a FIFO channel, any number of concurrent hint sources, and readers.
Reads are linearisable, and eviction is invisible to them. The
**implementation layer** is proved too:
* `Snapshot::apply` (merge, normalise, compact) implements the abstract
  update;
* all four vector-commitment schemes keep a commitment that is a function of
  the set;
* the value arena never frees a chunk that a live revision still references.

Everything is machine-checked with no `sorry`. Rust ↔ Lean correspondence:
[TRACEABILITY.md](TRACEABILITY.md), generated by `scripts/check_trace.sh` against
the pinned submodule commit.

Note: this proof has not been human-reviewed. Trust with care. 

## Building

The toolchain is a project-local copy of Lean 4.35.0 (core only, no Mathlib)
in `.toolchain/`:

```sh
git submodule update --init         # or clone with --recurse-submodules
source ./env.sh
lake build                          # checks every proof
lake env lean scripts/Audit.lean    # lists the axioms the main theorems use
scripts/check_trace.sh              # regenerates TRACEABILITY.md
```

To use VS Code instead, install `elan` (the Lean extension offers this). It
reads `lean-toolchain` and fetches the same version.
